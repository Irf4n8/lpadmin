Race Condition Test Cases – BlackTrader
Testing Type: Race Condition / Network Throttling / Browser Switching / Multi-Tab / Concurrency

Goal: Break the trading platform by changing browser state or network speed while orders and other operations are processing.

Focus Areas: Duplicate orders, missed executions, stale prices, incorrect P&L, order-state mismatches, synchronization failures.

1. Network Speed Testing Setup
Open Chrome DevTools → Network → Throttling → Select a network profile.

Select a network condition:

Fast connection

Slow 3G

Offline

Unstable / intermittent connection

Slow network test: Select Slow 3G or a custom throttling profile. Submit an order and perform another action before the first response arrives.

Note: Chrome Network throttling primarily affects browser requests. WebSocket behavior and server-side copy execution require separate verification.

3. Browser Switching and Multi-Tab Race Conditions
Use Chrome and Edge, or two Chrome windows with the same account.

For session-isolation tests, use separate browser profiles.

ID	Test Scenario	Bug to Identify
BR01	Open same account in Chrome and Edge → Place BUY simultaneously	Duplicate or unintended orders
BR02	Chrome places BUY → Edge closes position immediately	Incorrect final position
BR03	Chrome modifies SL → Edge modifies SL simultaneously	Stale SL value or inconsistent UI
BR04	Chrome cancels pending order → Edge modifies same order	Cancelled order reappears
BR05	Chrome places order → Immediately close Chrome	Missing acknowledgement or duplicate order after reopen
BR06	Place BUY in Chrome → Switch to Edge before response	Edge shows stale order status
BR07	Open same account in two tabs → Close same position simultaneously	Double close or reverse position
BR08	Chrome switches broker → Edge places order	Wrong broker selection or routing
BR09	Chrome changes chart symbol → Edge executes trade	Wrong symbol used in order
BR10	Log out in Chrome while Edge submits order	Incorrect session handling
BR11	Refresh both browsers during order execution	Incorrect trade synchronization
BR12	Chrome modifies TP → Edge closes position	TP modification applied to closed position
BR13	Browser A edits watchlist → Browser B deletes same watchlist	Stale data or unexpected recreation
BR14	Two tabs save the same algo settings simultaneously	Silent overwrite or mixed settings
BR15	Switch between tabs rapidly during active trading	Missing live updates after tab resumes
Important: Two deliberate BUY clicks can legitimately create two orders if the platform permits repeated submissions. The race-condition bug is an unintended duplicate submission from one logical action, or a violation of the platform's order controls.

6. Step-by-Step Manual Race Test – NET03 (Disconnect Immediately After BUY)
Execution Checklist (P0):

Open BlackTrader using a paper trading account.

Open Chrome DevTools → Network.

Select Slow 3G.

Prepare a BUY Market order.

Click BUY once.

Immediately change Network throttling to Offline before the response arrives.

Wait a few seconds, then restore Online.

Check Orders, Positions, History, and broker execution records.

Repeat 10–20 times with different disconnect timings.

Expected Result:

The order must have a single authoritative final state.

If the broker accepted the order before disconnection, it must appear after reconciliation.

If rejected, no position should exist.

An unknown response must not cause an accidental duplicate when retried.

Two browsers + SL modification	Stale updates
8. How to Confirm a Race-Condition Bug
After each test, verify the following:

Order ID: Was one logical order submitted more than once?

Execution ID: Did the broker execute duplicate trades?

Quantity: Does the final position match the intended executed quantity?

Account: Was the order routed to the selected broker?

Status: Do Orders, Positions, and History agree?

Recovery: Does the UI reconcile after reconnect without requiring a new order?

Logs: Are there repeated API submissions, retries, or out-of-order WebSocket messages?

For stronger evidence: Capture request timestamps, client request IDs, broker execution IDs, and screenshots before and after the race.

9. Priority Scenarios to Start With
Start with these six scenarios — they have particularly high potential to expose serious trading-platform concurrency defects:

NET03 – Disconnect immediately after BUY

NET07 – Click Close Position repeatedly on slow internet

BR07 – Two tabs close same position simultaneously

BR08 – Chrome switches broker → Edge places order

CP04 – Follower clicks Unfollow on slow internet → Master places BUY
